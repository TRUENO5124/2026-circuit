## 一、范围调整

原始设想同时包含图像识别、拓扑编辑、分析引擎、LaTeX 输出、benchmark、可视化标注和远期扩展，第一阶段复杂度偏高。

工程评审后，第一阶段范围收窄为 **本地优先的最小端到端闭环**：

- 建立 30 道题的评测集
- 设计电路拓扑中间表示
- 支持手动/半自动拓扑校正
- 实现模电基础分析引擎
- 输出 LaTeX 公式和分步骤解析
- 支持手机通过局域网把照片传到电脑端

第一阶段不追求完整云端服务、账号系统、完整 Multisim 式 IDE、任意电路自动分析或模拟 IC 设计。

## 二、已确认的工程决策

1. **类型化电路图作为唯一事实来源，SPICE / netlist 作为导出和校验层。**  
   技术方案论证详见 `projects/data-layer-technical-report.md`。前端画布、分析引擎、LaTeX 输出和评测集都围绕统一的类型化电路图读写。采用 **TypeScript + Zod** 作为数据模型的事实来源（Schema-as-Source-of-Truth），通过 `zod-to-json-schema` 自动生成 JSON Schema 供 Python 端消费。电路图采用 **NEC（节点-元件-连接）三元组**表示范式，与 KiCad 等工业 EDA 工具的数据模型对齐。元件定义采用**五维结构**（结构/参数/变体/分析/教学），同时驱动菜单渲染、端口校验、参数校验、分析策略选择和教学解释生成。校验器采用**"报告不阻断"**设计，返回 `ValidationIssue[]` 而非抛出异常，适配人工编辑工作流。

2. **视觉识别决策已取消。**  
   2026-06-12 曾选择“YOLOv8 元件检测 + PaddleOCR 参数识别 + OpenCV 拓扑提取”的三层架构，但该方案于 2026-07-23 退出当前项目范围。仓库不创建 `services/vision`，不训练或部署模型，也不把视觉精度作为验收指标；原技术论证仅保留为历史研究材料。

3. **编辑器采用 React Flow + 自定义电路元件节点的轻量网页电路图编辑器。**  
   技术方案论证详见 `projects/presentation-layer-technical-report.md`。采用 React Flow 作为基础库，通过自定义节点（React 组件）实现电路元件的 SVG 渲染，通过 Handle 组件实现引脚连接。第一阶段支持拓扑修正（拖拽元件、连线、修改参数），不做完整 EDA 软件。采用 React + TypeScript + Zustand 状态管理，与数据层的 Zod Schema 天然集成。

4. **分析引擎采用”课程规则层 + 符号/仿真工具层”的双层架构。**  
   技术方案论证详见 `projects/analysis-engine-technical-report.md`。课程规则层负责题型分类、分析策略选择、等效电路生成和分步骤解题过程；符号/仿真工具层负责 MNA 矩阵构建、符号求解和数值校验。采用插件式分析流水线（Strategy Pattern），通过策略注册机制支持题型扩展。符号计算核心采用 Lcapy（MNA 符号求解）+ SymPy（表达式化简/变换）+ PySpice（数值校验）的工具链。求解器采用三重保护机制（超时控制 + 复杂度限制 + 降级为数值求解），防止符号计算卡死。分析结果采用结构化 JSON 中间表示（AnalysisResult），实现”可验证分析”与”展示渲染”的分离。

5. **评测集采用多层标准答案。**  
   每道题不仅记录最终答案，还记录原图、题目文本、元件、节点、参数、类型化电路图、等效电路、关键方程、可接受等价表达式和知识点标签。

6. **输出系统区分”可验证分析结果”和”展示结果”。**  
   技术方案论证详见 `projects/presentation-layer-technical-report.md`。公式、图形标注、LaTeX 和文字解释都从结构化 `AnalysisResult` JSON 渲染，不让展示层重新生成答案。LaTeX 渲染采用 KaTeX（渲染速度 ~10ms，包体积 ~300KB），等效电路图通过 React Flow 从 CircuitGraph 直接渲染，报告导出支持 PDF/Word/LaTeX 三种格式。

7. **采用 TypeScript 前端 + Python 分析服务 + 共享 JSON Schema。**  
   前端负责交互，Python 负责符号计算、电路分析工具调用和评测；二者通过严格的数据结构通信。跨语言互操作的具体路径：Zod Schema（TypeScript 事实来源）→ `zod-to-json-schema` 导出 → JSON Schema 文件（中间契约）→ Pydantic Model（Python 镜像）。两端通过契约测试确保校验结果一致。

8. **采用数据驱动元件库。**  
   元件库主要服务于模电分析、数电分析和电路分析扩展。模拟 IC 设计只作为远期探索方向，不进入当前主线。

9. **分析引擎采用插件式分析流程和策略注册机制。**  
   第一阶段支持模电基础题，后续扩展电路分析和数电分析。

10. **采用分层测试矩阵 + 30 题自动评测。**  
    测试覆盖数据结构、评测集、分析引擎、展示输出和端到端交互。

11. **设定分层量化通过线。**  
    识别、分析和输出都有明确验收指标，避免评测集只作为展示材料。

12. **采用本地优先架构 + 局域网手机采集端 + 本地异步任务。**  
    技术方案论证详见 `projects/presentation-layer-technical-report.md`。手机扫码上传图片到电脑本地服务；所有处理都在电脑本地完成，不依赖云端或互联网。局域网手机上传采用 QR 码 + REST API + SSE（Server-Sent Events）方案：电脑端创建会话并显示 QR 码（含 URL Token，5 分钟过期），手机扫码打开上传页面（`<input type="file" capture="environment">` 拍照），上传后通过 SSE 实时通知电脑端。

13. **符号计算加入超时、复杂度限制和降级方案。**  
    避免某道复杂题导致本地软件长时间卡死。具体实现：L1 超时控制（10 秒阈值，中断后返回部分结果）→ L2 复杂度限制（表达式项数 >100 时化简后返回近似解）→ L3 降级方案（降级为 PySpice 数值求解，结果标记为"数值近似"）。

## 六、第一版验收指标

数据层：

- Zod schema 单元测试全部通过（接受合法图、拒绝非法图）
- JSON Schema 导出 artifact 存在且可被 Python jsonschema 库验证
- 19 个元件定义包含端口、参数单位、必填/可选标记、模型变体、分析标签和教学标签
- 3 个 Benchmark 样例通过 `validate:benchmarks` 校验
- 校验器对重复 ID、缺失端口、悬空节点、非法参数给出可操作错误

识别层：

- YOLOv8 元件检测 mAP@0.5 不低于 95%（基于 PCB 检测文献 93%–97% 的基准，教科书线稿预期更优）
- PaddleOCR 元件参数识别准确率不低于 90%（基于 PP-OCRv4 在中英文混排场景 85%–92% 的基准，加上电路领域字典微调）
- 节点连接识别准确率不低于 85%（基于 FLD 线段检测 + 节点聚类）
- 低置信度 / 可疑点召回率不低于 90%
- 端到端推理速度：单图全管线（预处理 + 检测 + OCR + 拓扑）在 CPU 上不超过 2 秒

分析层：

- 用户确认电路图后，目标求解量正确率不低于 90%
- 等效电路生成正确率不低于 85%
- 关键方程正确率不低于 85%
- 符号求解超时率不超过 10%（超时后降级为数值求解）
- 分步骤解题过程覆盖关键推理步骤不低于 90%
- 知识点标注覆盖率不低于 85%

输出层：

- LaTeX 渲染成功率不低于 95%（KaTeX 支持的命令范围内）
- 步骤说明覆盖关键知识点不低于 85%
- 用户修正后的端到端成功率不低于 90%
- 编辑器支持拖拽放置元件、连线、删除、修改参数
- 手机扫码上传到电脑端感知延迟不超过 3 秒
- 报告导出支持 PDF/Word/LaTeX 三种格式

## 七、主要失败模式与处理要求

| 流程 | 可能失败方式 | 测试要求 | 处理要求 |
|---|---|---|---|
| 手机上传 | 手机与电脑不在同一局域网 | 上传失败测试 | 提示连接失败和重试方式 |
| 图片导入 | 图片过大、格式不支持、方向错误 | 文件类型和大小测试 | 拒绝或自动修正并提示 |
| 图像处理 | 断线、阴影、低对比度导致拓扑不完整 | 分层识别测试 | 输出可疑点，不直接分析 |
| YOLOv8 检测 | 训练数据不足导致漏检/误检；密集元件 bbox 重叠 | mAP 评测 + 小样本鲁棒性测试 | 使用 COCO 预训练权重微调 + Mosaic/MixUp 增强；NMS 后处理；置信度阈值过滤 |
| PaddleOCR 识别 | 数学符号混淆（Ω→Q, β→B, μ→u）；小字号低分辨率 | 电路参数字典评测 | 构建电路领域专用字典微调；后处理规则纠正（R 后只能接 Ω/kΩ/MΩ） |
| 导线检测 | 线段交叉误判；元件引脚端点连接判定不准 | FLD + 节点聚类评测 | FLD 合并共线段；引脚端点聚类阈值调优；用户交互确认兜底 |
| 拓扑确认 | 用户遗漏未连接端口 | 数据结构和界面校验 | 阻止分析并高亮问题 |
| 数据结构 | 前后端字段不一致 | JSON Schema 契约测试 | 返回字段错误 |
| Zod-Pydantic 不一致 | Schema 演进后两端校验结果不同 | 契约测试（TS 校验 vs Python 校验比对） | 以 JSON Schema 为中间契约，两端都从 Schema 生成/校验 |
| Schema 版本不兼容 | 新版 Schema 无法解析旧版 Benchmark JSON | 语义化版本号 + 向后兼容测试 | 新增字段必须可选；提供迁移脚本 |
| 元件定义遗漏 | 图像识别出新元件类型但未在定义中注册 | 元件定义覆盖率测试 | 未知元件降级为 warning，编辑器允许手动添加 |
| 分析策略 | 题型分类错误 | 策略选择测试 | 允许手动选择分析策略 |
| 符号求解 | 表达式过复杂或超时 | 超时和复杂度测试 | 三重保护：超时控制→复杂度限制→降级为 PySpice 数值求解 |
| 分析策略 | 题型分类错误导致分析流程错误 | 策略选择测试 + 5 类题型覆盖 | 允许用户手动选择分析策略；策略 can_handle() 返回 false 时自动跳过 |
| 非线性 DC 工作点 | Lcapy 不支持非线性电路的 DC 分析 | 分段线性化测试 | 课程规则层先做工作区假设和分段线性化，再调用 Lcapy 求解线性化电路 |
| 符号-数值不一致 | 符号解代入数值后与 SPICE 结果不符 | 符号-数值比对测试 | PySpice 数值校验，差异超过容差时发出警告 |
| SPICE 校验 | 本地工具缺失或运行失败 | 适配器失败测试 | 跳过校验并提示依赖缺失 |
| LaTeX 输出 | 公式不可渲染或变量不一致 | LaTeX 渲染测试 | 标出失败公式，保留结构化结果 |
| 编辑器连线路由 | React Flow 默认路由不适合电路图 | 连线路由测试 | 自定义正交路由组件；必要时回退到手动路径 |
| 手机上传 | QR 码过期、手机无法访问局域网 | 会话过期和网络测试 | 提供手动 URL 输入降级方案；显示过期提示和刷新按钮 |
| 报告导出 | PDF 样式不一致、Word 公式渲染异常 | 导出格式测试 | 使用 CSS @media print 精确控制 PDF 样式；Word 导出使用 docx 库的公式支持 |
| 批量评测 | 单题失败中断全部评测 | 批处理隔离测试 | 单题失败后继续后续题 |

关键要求：任何失败都不能静默吞掉，必须进入警告或错误信息，并在界面中展示。

## 九、实现任务

- [ ] **T1（P1，人工约 2 天 / AI 辅助约 4 小时）**：定义类型化电路图作为系统唯一事实来源。技术论证详见 `projects/data-layer-technical-report.md`。采用 Zod 定义 `CircuitGraph`、`ComponentInstance`、`Connection`、`Node` 等核心 schema，通过 `zod-to-json-schema` 导出 JSON Schema artifact，实现 TypeScript ↔ Python 跨语言互操作。NEC 三元组表示范式与 KiCad 数据模型对齐。
- [ ] **T2（P1，人工约 3 天 / AI 辅助约 6 小时）**：建立数据驱动元件库。19 个元件定义采用五维结构（端口/参数/模型变体/分析标签/教学标签），覆盖无源元件、独立源、受控源、二极管、BJT、MOSFET、JFET。元件定义同时驱动菜单渲染、端口校验、参数校验、分析策略选择和教学解释生成。
- [ ] **T3（P1，人工约 5 天 / AI 辅助约 1 天）**：实现插件式分析流程和第一批模电策略，并生成可在解题界面展示的等效电路图。技术论证详见 `projects/analysis-engine-technical-report.md`。采用 Lcapy + SymPy + PySpice 工具链，MNA 矩阵建模，Strategy Pattern 策略注册。第一批策略覆盖二极管分析、BJT 直流偏置、BJT 交流小信号、MOS 直流偏置、MOS 交流小信号共 5 类题型。
- [ ] **T4（P1，人工约 3 天 / AI 辅助约 6 小时）**：加入符号计算超时、复杂度限制和降级方案。三重保护机制：L1 超时控制（10 秒）→ L2 复杂度限制（表达式项数 >100）→ L3 降级为 PySpice 数值求解。
- [ ] **T5（P1，人工约 4 天 / AI 辅助约 1 天）**：实现本地服务、SQLite 任务队列和 worker。

- [ ] **T7（P2，人工约 3 天 / AI 辅助约 6 小时）**：实现手机局域网扫码上传流程。采用 QR 码（qrcode.react）+ REST API + SSE 实时通知方案，手机端使用 `<input type="file" capture="environment">` 拍照上传。
- [取消] **T8**：原计划实现 YOLOv8 + PaddleOCR + OpenCV 本地图像候选拓扑生成流程。以下子任务均不执行：
  - T8a：YOLOv8 环境搭建 + COCO 预训练模型 POC 验证（1–2 天）
  - T8b：电路图数据集收集 + 标注（LabelImg/CVAT，200–500 张，1–2 周）
