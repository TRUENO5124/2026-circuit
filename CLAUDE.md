# Project Guidelines

## Current architecture and documentation (2026-10-19)

Computer vision remains planned for a later phase after the software body is completed; it has not been canceled.

The primary client is the native WinUI 3 project at `apps/desktop-winui/CircuitAssistant.csproj` (.NET 9, XAML, Win2D). `MainWindow` navigates directly to `AnalysisStudioPage`. The solve button invokes the C# netlist/classifier/strategy pipeline in-process; a dedicated teaching strategy that rejects a linear network falls back to the in-process complex MNA 2.0 analyzer (`Engine/Linear/LinearNetworkAnalyzer.cs`) for DC steady state / AC phasors. Teaching strategies now cover RC/RL, RLC, a single NPN **or PNP** BJT (four bias subtypes + common base + **common collector emitter follower**), **diode nonlinear circuits** (`Engine/Nonlinear/DiodeModel.cs` + `Engine/Strategies/DiodeCircuitStrategy.cs`: rectifiers, filters, limiters, clampers, peak detector, DC bias) and **single-transistor enhancement/depletion NMOS/PMOS and N/P-channel JFET amplifiers** (`Engine/Nonlinear/MosfetModel.cs` + `Engine/Strategies/MosfetAmplifierStrategy.cs`: common source/source-resistance/bypassed, common drain, common gate; Level-1 square law for enhancement and depletion MOS, Shockley `ID=IDSS·(1−VGS/VGS(off))²` with `K=IDSS/VGS(off)²` for JFET; MOS K/λ and JFET IDSS are editable in the inspector and persisted in the project file). Teaching results are DISPLAYED the textbook way (2026-10-18 round 7): BJT/MOSFET Q-points, AC metrics, summaries and step numbers follow the textbook estimation method, with every intermediate display value rounded to at most two decimals in its engineering unit (`Services/TeachingDisplay.cs`, AwayFromZero) and the rounded value fed into the next formula; formulas are never algebraically simplified (`(1+β)` stays). The Thévenin-exact solution is kept backend-only in `QPointInfo.ExactIbq/ExactIcq/ExactVceq` and the first step's `Values` (diagnostics/tests only, NOT bound in the UI). BJT/MOS derivations are grouped into DC-equivalent-circuit then AC-equivalent-circuit phases (`SolutionPhase` in `Engine/PedagogicalSolution.cs` → `AnalysisResult.StepGroups` + grouped cards in `Views/AnalysisStudioPage.xaml`); BJT common-emitter/common-base are 5 steps, common-collector 6, MOSFET 7 (DC first, electrolytic polarity checks belong to DC). All teaching display values (BJT/MOS plus RC/RL/RLC/MNA/diode/report) keep at most two decimals; region validation uses the unrounded loaded bias solution (including the BC junction condition). Missing Re is handled with the loaded base-loop equation. If the unloaded-divider estimate violates the region while the loaded solution is active, use a loaded, rounded teaching chain instead. Genuine cutoff/saturation and numerical failure are distinct. See projects/operating-region-validation-20261019.md. Round 8 (2026-10-18) adds BJT signal-source internal resistance Rs recognition (exactly one resistor between the AC source and the input coupling capacitor, e.g. `vs→R6=50 Ω→C3=47 μF electrolytic→base`; multiple/compound source networks still fail with a diagnostic message), electrolytic input coupling capacitors via their +/- pins (polarity check appended in the DC phase), source voltage gain `Aus = Av·Ri/(Rs+Ri)` (common base `Au·ri'/(Rs+ri')`) exposed through `AcParametersInfo.HasSourceResistance/SourceResistance/SourceVoltageGain` and shown in the live-metrics card and report export only when Rs is identified, and the lower-cutoff input time constant `τ1=(Rs+Ri)·C1`; MOSFET amplifiers still do NOT support a source resistance. Saving a project now preserves `ProjectName` (falls back to the file name only for an untitled "未命名电路工程") — the old defect overwrote textbook example names on every save and broke the generators' `--verify` project-name checks (D06 restored to "双向限幅电路（双管双偏置）"). Round 9 (2026-10-18) makes the BJT small-signal parameters editable and persistent: every BJT element carries `BjtRbb` (Ω, 0 = teaching default: 200 Ω for common emitter/collector, 50 Ω for common base) and `BjtRbe` (Ω, 0 = compute from the Q point; >0 = question-given r_be = h_ie used as-is, never re-rounded), persisted in `CircuitProjectData` (format still 1.2.0; older files default to 0 = auto). The engine reads them for every BJT subtype (four bias types, common base, common collector, NPN/PNP), uses the actual r_bb' in the rbe/h_ie step text/formulas (no hard-coded 200/50), and reports `rbb_ohm`/`rbe_ohm`/`rbe_source` (`computed`|`given`) in step Values; invalid backend values (non-finite/negative) fail explicitly. The UI exposes two editors — the selected-BJT inspector card and "参数设置 → 三极管模型与信号源特性" Group 3 — backed by `RbbNumber`/`RbeNumber` macro parameters two-way synced to BJT elements; invalid UI input falls back to 0 = auto. Default 0 keeps every previous numeric result unchanged. Round 9 has NO ui-capture window acceptance (per user request): console regressions + build only, the new editors' real-window appearance/interaction remains unverified. One BJT plus a diode stays `BjtAmplifier` and is rejected by the BJT strategy; multi-stage or mixed-transistor nets (>=2 transistors) classify as `MultiStageAmplifier/"Cascade"` and are explicitly rejected via the reserved `IMultiStageAnalysis` interface (cascade solving deferred to future project planning). `examples/circuit-models/` holds 29 native `.circuit` teaching files (D01-D07, B01-B16, M01-M06) generated by `tools/CircuitModels.*`; JFET and depletion-mode MOSFETs are recognized, drawn and solved by the teaching strategies (JFET gate-junction forward bias fails explicitly, a missing/non-positive IDSS fails explicitly, and a variable-resistor-region operating point only reports the region and stops the AC small-signal derivation, never a pseudo gain; implementation record: projects/fet-depletion-jfet-strategies-20261019.md). Component symbols are generated by `Models/SymbolGeometry.cs` (pure geometry used by both Win2D canvas and symbol cards): the PNP default symbol has its emitter on top and collector at the bottom (NPN keeps collector on top), and every element supports an ALT+X horizontal mirror whose pins, wires and WireTap junction nodes are kept in sync by `CircuitElement.GetPinWorldPosition()` and `Models/CircuitWireSync.cs`; N/P JFETs follow IEC 60617, VCC uses a Multisim-style power bar. LaTeX formulas are rendered by `Controls/MathFormulaView` on a Win2D `CanvasControl`: the pure-C# `Math/` parser + layout engine (`MathNode`/`MathLatexParser`/`MathLayoutEngine`) draws true sub/superscripts (0.72×), stacked fractions, radicals, bmatrix/pmatrix/cases/array matrices, Greek letters and `\mathbf`, wraps at the available width (base font size 16, height auto-fits, CJK font fallback), and the copy-LaTeX button is kept; known limits are array vertical bars not drawn, over-wide atoms scaled to fit, no canvas text selection, and `\overline/\vec/\tilde` decorations not drawn. Reports are exported natively by `Services/ReportExportService.cs` (Markdown, LaTeX+circuitikz, Word .docx, HTML) and Web/Python `CircuitGraph` JSON can be imported one-way by `Services/WebCircuitGraphImporter.cs`. React/HTML, Zod, FastAPI and Python/SymPy remain separate prototypes, not the desktop runtime pipeline.

## Skill routing

When the user's request matches an available skill, ALWAYS invoke it using the Skill
tool as your FIRST action. Do NOT answer directly, do NOT use other tools first.
The skill has specialized workflows that produce better results than ad-hoc answers.

Key routing rules:
- Product ideas, "is this worth building", brainstorming → invoke office-hours
- Bugs, errors, "why is this broken", 500 errors → invoke investigate
- Ship, deploy, push, create PR → invoke ship
- QA, test the site, find bugs → invoke qa
- Code review, check my diff → invoke review
- Update docs after shipping → invoke document-release
- Weekly retro → invoke retro
- Design system, brand → invoke design-consultation
- Visual audit, design polish → invoke design-review
- Architecture review → invoke plan-eng-review
- Save progress, checkpoint, resume → invoke checkpoint
- Code quality, health check → invoke health
